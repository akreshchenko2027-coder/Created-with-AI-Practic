# ПР10. Надійний AI-сервіс і AI UX

Матеріали до десятої практичної роботи. Повний текст завдання, критерії приймання й контрольні запитання — у документі `ПР10.pdf`, виданому до заняття.

## Задача коротко

Оператор підтримки «Сузірʼя» відповідає на звернення клієнтів. Факти — номер заявки, строки, куди привезти товар — він уже встановив (у ПР9 це робив workflow); лишилося написати відповідь людською мовою. Модель складає **чернетку**, оператор її редагує й надсилає.

Один виклик моделі ви робили ще в ПР3. Тепер цей виклик стоїть у застосунку, яким користуються весь день: провайдер відповідає по 10–20 секунд, іноді повертає 429 або 5xx, ключ може протермінуватися, а оператор, який не бачить, що відбувається, натискає кнопку ще раз. Тому в цій роботі модель — не головне. Головне — усе, що між HTTP-ендпоінтом і моделлю: **абстракція провайдера**, **таймаути**, **обмежені повторні спроби**, **контрольовані помилки**, **обмеження частоти**, **фонова генерація з потоком фрагментів**, **скасування** і **підставний провайдер**, з яким усе це можна перевірити без ключа.

## Що в цій папці

| Файл | Призначення |
|---|---|
| `app/` | Застосунок: провайдери, шлюз надійності, фонові задачі й вебінтерфейс |
| `samples/requests.json` | Вісім звернень із фактами, які встановив оператор, і прикладом відповіді — для підставного провайдера |
| `requirements.txt` | Залежності роботи |
| `.env.example` | Зразок налаштувань: провайдер і запасний варіант, доступ до моделі, таймаути, спроби, одночасність, ліміт на клієнта, поведінка підставного провайдера |
| `check_env.py` | Перевірка середовища, зразків і пробного streaming-запиту |
| `eval/` | Перевірка стійкості й того, що бачить оператор, за переліком сценаріїв |

```
app/
├─ main.py                веб-рівень: сторінка, /api/drafts, потік подій, скасування
├─ providers/
│  ├─ base.py             контракт провайдера
│  ├─ openai_compat.py    OpenAI-сумісний провайдер
│  └─ mock.py             провайдер для локальних перевірок
├─ gateway.py             таймаути, повтори, одночасність і запасний варіант
├─ jobs.py                фонова генерація, події й скасування

├─ drafting.py            запит до моделі й перевірка чернетки

└─ templates/index.html   сторінка: звернення, чернетка, скасування, повтор, перелік
```

Сторінка показує звернення з фактами, замовляє чернетку, слухає потік подій і відображає стан генерації, спробу, провайдера, запасний варіант і час до першого фрагмента. Текст надходить частинами в поле, яке можна редагувати; доступні скасування, повтор, копіювання, перегляд останніх чернеток із відтворенням подій і пʼять послідовних запитів для перевірки ліміту.

## Початок роботи

1. **Середовище:**

   ```bash
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   copy .env.example .env
   ```

   Для macOS і Linux активація середовища — `source .venv/bin/activate`, копіювання — `cp .env.example .env`. За замовчуванням використовується `mock`, тому Ollama й ключ для звичайного запуску не потрібні. Щоб перевірити справжню генерацію через Ollama, змініть `LLM_PROVIDER` на `openai` і виберіть модель, встановлену локально.

2. **Перевірка:**

   ```bash
   python check_env.py
   ```

   У режимі `mock` скрипт перевірить роботу без ключа. Для вимірювання реального провайдера встановіть його в `.env`; скрипт покаже час до першого фрагмента й загальний час відповіді.

Запуск застосунку з папки `pr10`:

```bash
uvicorn app.main:app --reload
```

Далі відкрийте http://127.0.0.1:8000. Прапорець `--reload` перезапускає процес при зміні файлів — разом із реєстром чернеток у памʼяті; для перевірки перезавантаження сторінки запускайте без нього.

## Що очікує сторінка

Замовлення чернетки — `POST /api/drafts` з `{"request_id": "d01", "client": "…"}`; у відповідь — знімок чернетки (`Draft` з `app/jobs.py` через `draft_to_dict`): `draft_id`, `status`, `text`, `attempts`, `provider`, `model`, `fallback`, `error`, `usage`, `elapsed`, `warnings`. Якщо замовлення відхилено, сторінка покаже тіло помилки: `{"detail": "…"}` або `{"error": {"kind": "…", "message": "…", "retryable": …, "request_id": "…"}}` — і заголовок `Retry-After`, якщо він є.

Далі сторінка відкриває `GET /api/drafts/{id}/events` і розуміє події `status`, `delta`, `done`, `error`, `cancelled` (їхні поля описано в `app/jobs.py`); інші показує в журналі як є. Статуси чернетки: `queued`, `running`, `done`, `failed`, `cancelled`. Скасування — `POST /api/drafts/{id}/cancel`; перелік — `GET /api/drafts`; знімок — `GET /api/drafts/{id}`; налаштування для шапки — `GET /api/health`.

## Реалізовані частини

| Де | Що зробити |
|---|---|
| `app/providers/` | Потоковий OpenAI-сумісний клієнт і mock із керованими затримками та збоями |
| `app/gateway.py` | Таймаут спроби, бездіяльності й загального бюджету; обмежені повтори, конкурентність, скасування й fallback |
| `app/jobs.py`, `app/main.py` | Фонові чернетки, журнал подій, SSE, скасування й нормалізовані HTTP-помилки |
| `app/limits.py`, `app/drafting.py` | Ліміт на клієнта, запит із підтверджених фактів і попередження для чернетки |
| `eval/` | Сценарії та висновки за фактично виконаними перевірками |

Перевірки й результати описані в `eval/README.md` та `eval/findings.md`.

## Перевірка

- `python -m unittest discover -s tests -v` — 16 тестів пройшли.
- `python -m compileall -q app tests check_env.py` — успішно.
- `python check_env.py` у режимі `mock` — середовище й зразки пройшли перевірку.
- Через Ollama `gemma3:4b` перевірено пʼять реальних звернень; заміри наведені в `eval/findings.md`.
- У браузері перевірено генерацію, відтворення завершеної чернетки після перезавантаження, збереження ручної правки після відмови від повтору й обмеження пʼяти послідовних запитів.
- Окремі перевірки збоїв і межі виконаного описані в `eval/findings.md`; невиконані сценарії не позначаються як перевірені.
