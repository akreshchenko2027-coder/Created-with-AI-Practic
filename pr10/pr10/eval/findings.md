# Висновки перевірки ПР10

## Налаштування й реальні вимірювання

Застосунок за замовчуванням працює з `mock` без ключа. Для реального запиту використано локальний Ollama через `http://localhost:11434/v1`, модель `gemma3:4b`, одинарну спробу, таймаут спроби 90 с, бездіяльності 30 с і загальний бюджет 120 с. Ці збільшені значення задавалися лише на час вимірювання; робочі налаштування залишені з таймаутами 20/20/45 с і трьома спробами.

| Звернення | До першого фрагмента | Загалом |
|---|---:|---:|
| d01 | 3,44 с | 5,16 с |
| d02 | 2,31 с | 3,52 с |
| d03 | 2,36 с | 4,06 с |
| d04 | 2,34 с | 4,47 с |
| d05 | 2,20 с | 3,44 с |
| **Середнє** | **2,53 с** | **4,13 с** |

Перший холодний запит через `check_env.py` зайняв 7,74 с до першого фрагмента і 8,96 с загалом. Тому ліміт бездіяльності збільшено з початкових 8 до 20 секунд; 20/20/45 секунд залишають запас для холодного запуску, не вимикаючи обмеження загального часу.

Під час повторної перевірки реальний запит через шлюз і Ollama `gemma3:4b` завершився успішно: перший фрагмент через 7,34 с, повна відповідь за 8,69 с. `qwen3:4b` локально повернув 198 streaming-фрагментів без тексту для пробного запиту; цей результат не класифікувався як помилка шлюзу.

## Автоматичні перевірки

Додатково тест підтвердив, що ліміт знову приймає запит після завершення вікна, а `Retry-After`, який вміщується в бюджет, витримується перед повтором.

`python -m unittest discover -s tests -v` — 19 тестів пройшли. `python -m compileall -q app tests check_env.py` і `python check_env.py` у режимі `mock` також пройшли. Після повторної перевірки HTTP-запит до запущеного застосунку створив чернетку зі статусом `done`; невідоме звернення повернуло нормалізований 404.

Повний HTTP-прохід через Ollama також перевірено: `POST /api/drafts` для `d01` завершився зі статусом `done`, моделлю `gemma3:4b`, перший фрагмент надійшов за 3,00 с, загалом — 4,45 с.

Не перевірялися реальна відповідь 429 від Ollama та реальний збій автентифікації; відповідність їхніх SDK-помилок внутрішнім видам окремо перевірена синтетичними винятками. Очікування повної хвилини не вимірювалося — відновлення після вікна перевірено коротким тестовим інтервалом. Чернетки зберігаються в памʼяті процесу й зникають після його перезапуску.
